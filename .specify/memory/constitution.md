# Constitution — Vibe Editing V2

الحالة: مبادئ مقترحة للخطة. نسخة 0.1 — 2026-10-10.

1. المصدر لا يتغير: القص والترتيب والمؤثرات تعليمات قابلة للتراجع، ولا تعيد كتابة الأصل.
2. نسخة تحرير واحدة: جميع القرارات المرئية والمسموعة والقوالب المستخدمة تدخل ProjectDocument أو مراجع ثابتة بإصدارات داخله.
3. نفس أوامر التحرير للإنسان والـAI؛ لا مسار خفي يتجاوز التحقق أو Undo.
4. الوقت دقيق: أوقات المصدر والـsequence وداخل المشهد متميزة. لا نجمع float seconds عبر آلاف القصات.
5. كل تعديل مركب ذري: ينجح كله أو لا يغيّر المشروع. تعارض الإصدارات لا يكتب فوق التعديل الأحدث.
6. التصدير يرتبط بـrevision ثابتة، ويستعمل أصولًا وقوالب وخطوطًا مثبتة؛ لا يقرأ أحدث حالة قابلة للتغيير.
7. كل قدرة جديدة تشمل الحفظ والتراجع والمعاينة والتصدير والتحقق من الفشل في مرحلتها.
8. جودة الفيديو الطويل شرط من البداية؛ اختبار مبكر، ثم قياسات مستمرة، ثم اختبار إصدار شامل.
9. المعالجة الثقيلة مهام durable خارج طلبات الواجهة؛ إعادة المحاولة لا تنشئ تعديلًا أو مصروفًا مكررًا عمدًا.
10. محتوى الفيديو والـkit مدخلات بيانات؛ لا يعطيان الـAI سلطة على الملفات أو النظام أو الأسرار.
11. Local وHosted يشتركان في domain والعقود؛ الاختلاف في التخزين والتنفيذ والهوية عند seams محددة.
12. لا يُنسخ تعقيد القديم تلقائيًا. كل Module يحتفظ بمنطق حقيقي خلف Interface صغيرة؛ لا طبقات تمرير بلا وظيفة.
13. القرارات والافتراضات والدليل منفصلة. لا نستنتج صحة الأداء من screenshot أو نجاح فيديو واحد.
14. الخطط تقلل الأخطاء ولا تضمن انعدامها. اكتمال مهمة يحتاج دليل قبول مسجلًا.
15. النطاق يتغير عبر تحديث spec والآثار المرتبطة؛ لا تضاف ميزة كبيرة جانبية تحت اسم إصلاح صغير.
16. طبّق قواعد التصميم الشخصية بصيغتها المكيّفة للمشروع في [Engineering rules](../../docs/12-engineering-rules.md). افصل transport/application/domain/infrastructure، ولا تنقل وصفات C#/EF حرفيًا إلى TypeScript. خريطة التكييف توضح الاستبدالات المقصودة.

## تعديل المبادئ

أي تغيير يشرح السبب والبدائل وأثره على الوثائق والاختبارات في سجل القرارات. طلب المستخدم الأحدث يتقدم على الافتراضات والتوصيات هنا.
