# Phase 00 — إثبات الأساس واختيار مسار التصدير

الحالة: مخطط، لم ينفذ.

## النتيجة

دليل تشغيل صغير يمرر media حقيقية من الاستيراد إلى preview/export، وقرار موثق عن ما نعيد استخدامه وأي renderer نعتمد.

## التبعيات والمتطلبات

لا توجد تبعية تنفيذ؛ اقرأ AGENTS.md وdocs/12-engineering-rules.md وdocs/01-research.md وdocs/07-decisions.md.

التغطية: D01–D05، ADR-01/02/04، O01–O03/O07.

## داخل النطاق

- تحديد الجهاز والمدد والدقة المرجعية؛ benchmark على عينات قصيرة وطويلة.
- مشهد عربي + صورة + source video + صوت + قصات + تغيير layout ضمن harness محدود.
- مقارنة renderer A، ثم B إذا لم يحقق A القيود؛ يشمل الأثر على parity وذاكرة/temp disk.
- تشغيل اختبارات domain القديمة ذات الصلة إن توفرت dependencies، وتحديد reusable slices.
- اختيار stack وjob transport وlocal runtime، وتثبيت نسخ dependencies المتوافقة.

## خارج النطاق

لا بناء لكل الواجهة، ولا AI Director أو حسابات عامة، ولا إعلان production readiness. الـharness تجربة هندسية؛ نتيجتها تنتقل للتنفيذ الإنتاجي ولا تحل مكانه.

## سيناريوهات القبول

- **P00-A1**: مصدر فيديو مع overlay عربي وقص وصوت ينتج preview وتصدير؛ marker frames والصوت متطابقان ضمن أهداف Quality.
- **P00-A2**: Q05 وQ06 يسجلان wall time وpeak memory وtemp disk وRTF وتفاوت cold/warm؛ إذا فشل أحدهما تظهر نتيجة no-go أو limit صريحة.
- **P00-A3**: مقارنة A/B أو تبرير الاكتفاء بـA، مع ملاءمة fonts/video codecs وأثر sparse graphics؛ ADR-04 تحدد renderer واحدًا.
- **P00-A4**: تقرير reuse يذكر الاختبارات التي شغّلت فعلًا وما تعذر تشغيله، وما يُنقل أو يُكيّف أو يُعاد تنفيذه داخل V2 الجديدة مع السبب؛ البناء في الريبو الجديد مؤكد.
- **P00-A5**: مواصفات الجهاز والـfixtures والقيود والإصدارات موثقة بما يكفي لإعادة التجربة؛ O01/O02 غير المجابتين تبقيان افتراضات لا حدود منتج مؤكدة.

## بوابة الخروج

لا تبدأ 01 مع renderer غير محسوم أو timing/parity فاشلين. يجوز تعديل الأهداف بدليل واضح مع إبقاء حدود الدعم صريحة.
