# Phase 08 — إصدار محلي موثوق

الحالة: مخطط، لم ينفذ.

## النتيجة

المستخدم يشغّل ويحدّث ويستعيد التطبيق على جهازه دون الاعتماد على جلسة تطوير مفتوحة.

## التبعيات والمتطلبات

Phase 07 ناجحة على media ممثلة للاستخدام.

التغطية: FR-13، D04 للنسخة المحلية.

## داخل النطاق

- launcher/setup وفحص runtime/ports/disk/tools والخدمات المطلوبة فقط.
- مكان بيانات واضح ونسخ احتياطية واستعادة project/assets manifest، وسياسة cache cleanup.
- schema migrations آمنة وتحديث/rollback متوافق مع البيانات.
- إعداد مفاتيح الخدمات خارج frontend، تشخيص logs منقحة، health/status وإيقاف jobs بأمان.
- اختبارات جهاز نظيف/مستخدم Windows بمسار عربي ومسافات؛ دليل استخدام ومشاكل شائعة.

## خارج النطاق

ليست مرحلة account SaaS/billing. desktop shell ليست مفروضة إلا إذا قرار Phase 00 أثبت ضرورتها.

## سيناريوهات القبول

- **P08-A1**: على بيئة Windows نظيفة يمكن الإعداد والتشغيل واستيراد/تحرير/تصدير مشروع دون تشغيل أوامر يدوية غير موثقة.
- **P08-A2**: بعد إغلاق الواجهة وإعادة تشغيل الجهاز يستعاد المشروع والمهام وحالة unsaved وفق السياسة؛ لا تبقى orphan processes.
- **P08-A3**: backup تُستعاد إلى data directory أخرى مع جميع references والـassets المطلوبة؛ cache قابلة لإعادة البناء.
- **P08-A4**: تحديث schema من إصدار سابق يحفظ البيانات؛ فشل migration لا يترك نصف تحديث، وrollback/restore مجرّب.
- **P08-A5**: تعطيل الشبكة يبقي التحرير والحفظ والتصدير للأصول المتاحة صالحًا؛ AI/transcription cloud يظهران غير متاحين بوضوح.
- **P08-A6**: المفاتيح ليست في bundles/logs؛ localhost runtime محمي من origins غير مسموحة وطلبات بلا session، ولا يدّعي local profile صلاحية hosted.

## بوابة الخروج

إصدار محلي قابل للاستخدام المستمر، مع استعادة مجرّبة؛ لا نسمّيه جاهزًا للجمهور على الإنترنت بعد.
