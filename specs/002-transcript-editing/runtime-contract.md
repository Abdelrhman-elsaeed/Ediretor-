# Phase 02 runtime contract

Implemented local workflow, 2026-10-11. Extends Phase 01; its 600-second / 200-clip / 1080p30 export limits still apply. No renderer qualification, translation, synthesis, sync or templates are introduced.

## Revisions and immutable sources

SQLite migration `002-transcripts.sql` extends the job kind constraint without rewriting migration 001 or changing existing project/revision/receipt JSON. The migrator takes a write lock and rechecks each version, including concurrent API/worker startup. The v1 upgrade test checks retained projects/jobs and foreign keys.

Document schema 2 adds `transcriptRefs`, `displayCorrections` and `captionStyle`. Existing schema 1 documents/history/receipts remain readable; a new edit upgrades that document in memory. Old immutable revisions are not rewritten. Words are stored in immutable transcript records outside document/history JSON. Each reference pins transcript ID, source asset ID and normalized content hash. The application revalidates all references against the owned catalog.

Words carry stable `transcriptId:c<chunk>:w<index>` IDs, integer decimal-string microseconds, confidence, utterance ID and optional speaker. Provider/model/language/options, normalization version and returned model version(s) are retained. Raw JSON is separate from normalized words: fenced durable chunk checkpoints retain each provider response, and successful publication additionally stores an immutable raw-response file in the local asset store. No raw download route or key is exposed to the browser.

An instantaneous provider word receives a 1ms normalized interval. `dg-words-v2` accepts a word ending at most 2s past the actual source end, clamps there and uses the clamped interval for ownership midpoint. This fixes a captured real 161.287696s recording whose last word overran by 1.105927s; the former 1s bound rejected its entire transcript, and using the reported midpoint could also discard the final word. Both repairs retain `reportedEndUs` and `timingAdjustment` and enter the review filter. Reversed intervals, starts outside the source and greater overruns still fail. Existing `dg-words-v1` records remain readable and immutable. This is normalization with recorded provenance, not a change to audio/video or proof of acoustic alignment accuracy.

`AttachTranscript`, `CorrectWordText`, `DeleteWords`, and `SetCaptionStyle` pass through the existing Kernel, Session, save receipt, revision conflict, persisted undo/redo and browser recovery paths. Corrections belong to `(transcriptId, wordId)` and therefore affect every occurrence of that source. Deletion anchors include `clipId`, so deleting one appearance does not delete repeated appearances. Manual splits project a boundary-straddling word into two distinct occurrence spans. Attaching another transcription of an asset is an explicit undoable operation; it never rewrites a project as a worker side effect.

## Transcription

`POST /api/projects/:id/transcribe` accepts `{assetId, language, requestId}`. Languages are `ar-EG` (default), `ar`, `en`; model is `nova-3`. Official [model/language documentation](https://developers.deepgram.com/docs/models-languages-overview) lists Egyptian Arabic. Its `multi` language list does not include Arabic; we do not promise Arabic/English automatic code switching from that option. The [pre-recorded API](https://developers.deepgram.com/reference/speech-to-text/listen-pre-recorded) is called with actual mono 16kHz WAV bytes, `utterances=true`, `punctuate=true`, `smart_format=false`, `version=latest`. Returned actual model versions are pinned in the result rather than presenting `latest` as reproducible provenance.

Credentials come from server environment or ignored `.env.local`, loaded by the API and worker. Never put a key in a `VITE_*` variable. Restart both processes after changing it. A missing key is unavailable; a video without an audio stream is rejected before creating a transcription job. An audio stream containing silence may produce a valid zero-word transcript and a visible no-speech state.

The existing separate worker, SQLite lease, 500ms heartbeat, fencing, terminal status and cancellation machinery are reused. HTTP acceptance does not execute transcription inside the request. Submissions deduplicate identical request IDs and an already active asset/language job. A changed request-ID payload fails. A finished transcript can only be published once, inside the job completion transaction and under a live lease. Transcription never advances an editing revision.

Audio is processed sequentially in 120s ownership windows with 1s context on both sides, bounded WAV memory and a 120s provider deadline per request. Provider 429/5xx/network failures allow at most three requests, with bounded abortable backoff; credential/rejected-input failures fail immediately. Completed raw chunks survive worker death and explicit retry. Acoustic midpoint determines overlap ownership; same-text overlapping cross-chunk boundary words deduplicate. Actual repetitions within a chunk are preserved. Word IDs refer to the original chunk index even when a boundary word is removed.

As with ordinary remote APIs, a request interrupted after provider processing but before durable acknowledgement can be billed again on retry. Local receipts/checkpoints prevent intentional duplicate processing where completion is known; they cannot provide exactly-once execution at Deepgram. Maximum automatic worker recovery attempts remains three. The worker's overall 30-minute deadline also remains. Long-media cost/resource qualification is deferred.

## Conservative text cuts

All intervals are half-open. Group adjacent selected words within an occurrence; remove their speech and at most 40ms surrounding silence. Padding stops halfway to an unselected neighbour and never crosses an occurrence/source boundary. Convert boundaries outward to the 30fps grid, only where retained speech is not crossed. The integer timestamp representing frame `n` is `ceil(n × 1,000,000 / 30)`.

Overlapping retained acoustic intervals, rounding into retained speech and a retained fragment shorter than a frame are rejected with `AMBIGUOUS_WORD_BOUNDARY`. The selection remains available for extending it to adjacent words or using manual cuts. Merge touching intervals across boundaries; apply disjoint intervals from right to left in one atomic action. Source references and retained source offsets stay intact. Restoration uses the shared **Undo** action, restoring the exact pre-cut occurrence intervals; Redo reapplies that state. Independent restoration of an older deletion while retaining intervening edits is not provided.

## Captions

Caption cues derive from the edited sequence projection and corrected display text. Group within an occurrence/utterance; split on >600ms gaps, >3s spans or a two-line/32-codepoint line bound. An unbreakable word longer than the bound is an explicit overflow error. The renderer additionally measures actual glyph widths and rejects overflow rather than shrinking or clipping text. Source references remain required even for SRT/VTT download; unavailable pinned transcripts fail honestly.

Both preview and export execute the same `drawCaption` function on a 1920×1080 Canvas using Noto Sans Arabic, weight 600, 52px, 78px line spacing, 96px safe margin, centered white text and a dark backing rectangle. Arabic/mixed lines use Chromium's RTL shaping; English-only lines use LTR. Font bytes are pinned to SHA-256 `63111b5b2e074dd48cc67692e0a2726d86ee94c1c37fe8598257b7b4e87e869e`; the license/source remains in `apps/web/public/fonts`. No system font substitution is selected by the application.

Style contract `canvas-captions-v1`, actual Chromium version, Playwright 1.62.1 and the actual FFmpeg build stamp are pinned when enqueueing. The worker verifies the stamp and font hash before rendering. Changing runtime after enqueue fails instead of silently rendering with new versions. Preview uses the browser's own Canvas implementation: checked Chromium parity is documented, cross-browser rendering parity is not claimed.

The bounded export strategy reuses native cuts/audio composition. The worker rasterizes static transparent cue PNGs in Chromium, creates a sparse FFconcat stream with frame-based durations and blank intervals, and overlays it once during final H.264/AAC mux. Output is explicitly 30fps CFR and its exact frame count and full decode are validated. This adds one encode when captions are enabled; no caption-length transparent intermediate video or per-word FFmpeg graph is built. This is a Phase 02 caption strategy, not an alternative scene renderer or a restart of deferred Remotion benchmarks.

`GET /api/projects/:id/captions?revisionId=…&format=srt|vtt` exports edited times and corrected text. It rejects a stale revision or empty cues. The UI flushes Session edits first. Video export snapshots pin cue content together with the saved document/runtime/font; later corrections do not change an accepted job.

## UI and bounds

The editor uses one tool catalog/sidebar for media, transcript, captions, clip properties and jobs; only one tool drawer is visible at a time. Pointer/keyboard separators adjust drawer width and timeline height; these preferences are versioned local browser UI state, separate from editing revisions. Small screens use an overlay drawer. Preview preserves its 16:9 canvas instead of stretching to an independently constrained height.

The transcript shows fixed-height virtual paragraphs, bounded to six words/42 characters before a new row (a longer single word remains selectable with its full text in the tooltip). Paragraphs preserve utterance/occurrence boundaries and use explicit Arabic RTL/English LTR ordering; individual mixed word labels retain automatic direction. Word checkboxes are removed: pressing and dragging selects a complete-word range in either direction, across lines, paragraphs and virtual rows. Logical occurrence keys retain the range when its anchor scrolls offscreen; edge dragging automatically scrolls the viewport. A single click selects/seeks a word; Shift extends the range. Keyboard Enter/Space select, Shift+directional arrows extend, Ctrl/Cmd+A selects filtered words, and Escape clears. Changing search/review filters clears selection; Delete/Backspace outside text inputs invokes the same word cut action.

A floating action toolbar occupies reserved space below the text viewport and appears after selection ends, so it does not cover paragraphs or move them when a range is selected. Action descriptors make further commands possible without inserting controls between words. Current commands delete selected words and open spelling correction for a single selected word. Corrections and cuts continue through the same Kernel/Session/history; failed ambiguous cuts retain the selection and cuts remain bounded to 2,000 selected words. Caption configuration/downloads are in their own tool. Playback highlighting updates only mounted word classes; captions redraw only on cue transitions. The editor tree does not subscribe to each playback frame. Search/UI state is separate from revision state. Both caption download entry points flush Session edits and fetch the saved revision from the same server endpoint.

Explicit states cover loading, empty/import needed, silent source, no speech, unavailable service, queued/processing, failed, cancelled and shared save/conflict/recovery. Completed words require an explicit **Use transcript** command. Provider failure never supplies substitute text. The 60,000-word corpus in browser tests is clearly named synthetic stress data, injected only into a read-only UI response; it is not a provider or persistence fixture.

Normalized source transcript size is bounded to 100,000 words per record. Catalog responses materialize these bounded records; paging/streaming of many simultaneous large transcripts, worker chunk cost qualification and assistive-technology coverage are not established. The viewport bounds and 60k-word test establish mounted DOM behavior, not a 60-minute/4-hour rendering SLO.
